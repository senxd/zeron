# Custom features

Features on `personal` that upstream Zeron does not have. Update this table in the same change that adds, changes, or removes one.

When merging `upstream/main`, compare each row with the incoming upstream behavior. If upstream now provides the feature, delete the local implementation and remove the row. Leave the row when upstream only covers part of it, and note what is still local.

The personal update feed (`.cargo/config.toml`, `release_base`, `.github/workflows/personal.yml`) is fork plumbing. It stays out of this table.

| Feature | What it does |
| --- | --- |
| Model loadout | Settings → Model Loadout holds five slots filled by dragging models from provider lists. Each slot can have an activation shortcut. The model picker has a Loadouts rail that applies a slot to the current thread. Pi sessions keep the workspace model list. Cursor reasoning is sent as Cursor effort. Slot menus show a single Effort row when a model's effort rides a named option (e.g. Cursor's `reasoning_effort`) instead of a reasoning ladder. |
| Hide archive button | Sidebar view → Show → Archive. Unchecking it hides the archive button that appears when hovering a session row. The archive shortcut still works. |
| Sidebar disclosure | Pinned, Sessions, Archived, and project or device groups stay open or collapsed across launches. |
| Compact mode | Settings → Appearance toggle (default off) folds each turn's thinking, tool calls, and narration into one collapsed accordion that settles to "Worked for Xm Ys"; expanding still shows the work. From open upstream PR #456 — drop this row when it merges. |
| Grok and Devin accounts | Settings → Agents lists Grok and Devin provider cards with usage meters next to Claude Code, Codex, and Cursor. Detect/switch only; sign-in stays in `grok login` / `devin auth login`. From open upstream PR #459 — drop this row when it merges. |
| Transcript comments | Selecting agent text in the transcript stages it as a response annotation with an optional comment; the agent answers with `:zeron-annotation` markers that render as pills. From open upstream PR #496 — drop this row when it merges. |
| Folded Devin models | The Devin model list collapses raw variants into one row per family (SWE-1.6, SWE-1.5, Fusion) with reasoning levels and options for context window, thinking, fast mode, and Fusion lead/sidekick. Selections resolve back to the exact Devin variant at run time; loadout slots can store the options. From open upstream PR #446 — drop this row when it merges. |
| Folded Grok fast variants | Grok's `…-build-fast` model ids fold into the base row's Fast toggle instead of listing as a separate model; a run recomposes the advertised fast id when the toggle is on, and saved full ids pass through. |
| Engine restart on desktop update | Applying a desktop update also kickstarts the `sh.zeron.app` headless service after the app exits, so the relaunched GUI attaches to the new engine instead of the pre-update daemon. |
| Composer chip indicators | The model chip drops context-window choices from its suffix and shows the speed pick as a bolt icon for any provider toggle (serviceTier, fast mode). A small usage ring beside the chip shows the active provider account's tightest usage window (accent → amber ≥80% → red ≥95%), refreshed against the engine's usage cache. |
| New chat in sidebar groups | Hovering a project or device group header reveals a "+" left of the chevron that opens the new-session canvas bound to that group — the project, or a project-less session on the device for home/device groups. |
| Scheduled prompts | A clock button on the composer opens a popover with quick picks ("In 15 minutes", "Tomorrow 9:00 AM") and a free-form time field. The engine keeps the draft (full run request + optional new-chat spec) in a profile-local JSON store and fires it through the durable command plane — headed or headless, surviving restarts, deduped by stable message ids. The same popover lists upcoming and finished rows with cancel and run-now. |
| Devin rate-limit auto-continue | When a Devin run errors on a usage/rate limit (429 / quota / "limit reached" wording — never user stops), the engine parks a delayed re-dispatch until the quota window resets (probed via the Devin account's usage windows, 10-minute fallback, 24-hour cap). It notes the resume time on the errored turn, retries at most 4 times per streak, and any manual send or a completed turn reclaims the chat. |
| Resume on empty composer ("resme") | When the last turn was stopped or the session errored and the composer is empty, the send button becomes a restart icon. Clicking (or pressing Enter) re-queues the last user turn under its own message id, so the host resumes the stored harness session instead of writing a duplicate message. Requires a recorded harness session id. |
